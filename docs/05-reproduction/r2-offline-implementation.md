# R2-A — Offline mechanism candidate analysis (CPU-only)

**Status (2026-11-06): implementation and synthetic test phase.** This is a separate candidate-discovery path; it does not reproduce the original authors' directions, p50c mask or MATH-500 accuracy. The full R1 benchmark is still pending.

## Scope and non-claims

This stage implements the dimensional arithmetic described in the original Exp 8 method discussion, using **pre-collected matched diagnostic arrays**. The pipeline does not download or load Qwen, collect teacher-forced activations, consume test labels, edit checkpoints, or run GPUs.

- src/wsp/read/contrastive_direction.py: R−P mean across matched pairs, L2 normalization, leave-one-pair-out cosine checks. At least three unique pairs; nonfinite/degenerate directions rejected.
- src/wsp/read/neuron_score.py: per-column signed score = mean(R activation − P activation) × (direction · weight column). Deterministic ties and dimension checks.
- src/wsp/read/layer_attribution.py: descriptive projection of component deltas. **Observational only**; causal_supported remains false.
- src/wsp/repair/sparse_edit.py: immutable float32/float64 proposal W' = W − alpha × u × (uᵀW_selected), 0≤alpha≤6, exact nonselected column preservation. It is NOT official BF16 p50c replay.
- scripts/r2_offline.py: strict diagnostic manifest, input/weight SHA256, outputs candidate JSON only. Never writes edited model weights.

## Input contract

An NPZ generated by a separate approved probe collector must contain **exactly** these five fields:

    productive_states         [N, d_model]   # token-window aggregated
    repetitive_states         [N, d_model]   # matched to the same questions
    productive_activations    [N, d_ff]
    repetitive_activations    [N, d_ff]
    down_proj_weight          [d_model, d_ff] # float32 or float64

The adjacent JSON manifest must provide:

    {
      "split": "diagnostic",
      "allowed_for_selection": true,
      "pair_ids": ["diagnostic-pair-001", "diagnostic-pair-002", "diagnostic-pair-003"],
      "model_revision": "<exact 40-character model commit>",
      "tensor_name": "model.layers.15.mlp.down_proj.weight",
      "token_selection": "matched:last-16-token-average",
      "weight_sha256": "<sha256 of numpy C-contiguous tensor bytes>",
      "weight_shape": [1024, 3584],
      "weight_dtype": "float32"
    }

The input contract deliberately lacks answer keys, holdout labels, author-selected columns or other privileged final-repair artifacts. Pair IDs must be unique, and the manifest must describe the same model/layer/token positions as the actual probe generation. **A manifest declaration is not cryptographic proof that a collector kept holdout isolated.**

## Run and output

After installing CPU dependencies:

    python -m pip install -e '.[dev]'
    python scripts/r2_offline.py --probes /data/diagnostic.npz \
      --manifest /data/diagnostic.manifest.json \
      --out /runs/r2a/candidate.json --top-k 64 --alpha 1

The command is intentionally non-overwriting. The JSON records source/probe file hashes, data split, revision, target tensor, LOO stability, candidate direction, ranked columns, selected scores, edit norms, edited **in-memory** tensor bytes SHA256 and explicit unfulfilled gates. Do not register this JSON as a validated model patch.

CPU tests:

    python -m pytest -q tests/unit/test_r2_core.py

## Remaining scientific gates (do not claim completion)

1. Build audited Qwen teacher-forced probe extraction, consistent attention/MLP hook points and matched token spans; lock exact model/tokenizer revisions.
2. Gather four or more independent productive/repetitive contrast groups, label-shuffle and random-direction controls. Freeze the direction and mask without ever reading the final author mask/holdout.
3. Independently attribute candidate layers and components through actual **forward interventions**; observational alignment cannot establish causality.
4. Run alpha/top-k/single-layer/random-direction ablations on validation; use a **separate untouched holdout** and report negative outcomes and off-target regressions.
5. Complete R1 base/edited GPU MATH-500 paired benchmark and produce measurable evidence for R2 claims.

## Safety and validity

For local research use only. The in-memory sparse operator rejects duplicate/out-of-bounds columns and floating-point anomalies. It intentionally does not support BF16 checkpoint writeback; that requires separate, verified, allowlisted proposal-to-artifact tooling. Failed or low-stability direction evidence should lead to a No-Edit decision, not optimistic editing.
